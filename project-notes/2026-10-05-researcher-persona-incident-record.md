# Researcher Persona Incident Record（Researcher Persona インシデント記録）

Date: 2026-10-05
Status: VERIFIED DOCUMENT CHANGES / RUNTIME UNVERIFIED

本記録は、Education用Researcher GemのPersona適用不全インシデントと、その対策として行ったResearcher系Persona 4ファイルのv1.1改訂の内部記録である。改訂後の仕様の正本は各Persona本体であり、判断履歴の正本は `project-notes/RESEARCHER_PERSONA_DECISIONS.md`（2026-10-05）である。本記録はそれらの代替ではない。

## 1. Incident（事象）

Education用Researcher Gem（`GEM_RESEARCHER_FULL.md` v1.0 を Gem の `カスタム指示` に登録）に対し、Userが二次情報のWeb記事URLと「この情報は本当か？」という短い質問を入力した。Gemは次の挙動を示した。

1. 記事の内容を要約しただけで調査を完了した。
2. 一次情報（公式発表等）を確認せず、User提示の二次記事を確認済み事実・Evidenceとして提示した。
3. 回答前の作業メモに相当するテキストを回答へ混入させた。

| 項目 | 区分 |
|---|---|
| 上記3挙動 | UNVERIFIED（Gem自身のインシデントレポートとUser申告による。会話ログ実物は未確認） |
| 使用Persona が `GEM_RESEARCHER_FULL.md` v1.0 本文であること | User申告。本文の一致はRepository正本との照合でVERIFIED |
| Persona の登録先が Gem の `カスタム指示` であること | User申告 |

## 2. Cause（原因）

原因は未特定。

- v1.0 には、今回の挙動を禁止する規則が既に存在していた（3章「実際に確認していない情報を『確認済み』として提示しない」、4章「Evidenceを示せない情報は、確認済み事実として扱わない」、5章「二次情報しか確認できない場合は、そのことを明示します」）。本件は規則の欠落ではなく、既存規則が守られなかった事例である。（VERIFIED）
- Gem自身のインシデントレポートは、原因を「処理リソースの優先」「簡易応答パスの選択」「Personaの明示的呼び出しがなかったためのコンテキスト未再ロード」と説明している。これはAIの自己申告であり、裏付けがない。Personaは `カスタム指示` として常時適用される登録状態であったため、「呼び出しがなかった」という説明は登録状態と整合しない。（INFERENCE：仮説として扱い、原因として採用しない）
- 同レポートが運用対策として挙げた「指示の先頭に『Researcherペルソナで』と書く」は、上記の未検証の原因説明を前提としており、効果は未検証である。

### 3.2 追加・修正した規則の要旨と理由

| 規則 | 内容 | 理由 |
|---|---|---|
| 依頼の種類による区別 | 要約・説明だけの依頼は資料の範囲で回答し、外部検索を必須としない。資料の記述は確認済み事実として示さない。真偽・現在の有効性の確認依頼は、質問が短くても資料の要約だけで完了しない | 本件の直接の失敗（要約で調査完了）を防ぎつつ、要約依頼にまで外部検索を強制しないため |
| 資料の性質確認 | 提示されたことだけで信用せず、発行元・対象・版・公開日を確認する。公式発行元の一次情報で該当記述を確認できれば Evidence として使える | 公式仕様書の提示まで根拠から除外しないため |
| 主張ごとの振り分け | 一次情報で確認 → 確認済み（Reference：`VERIFIED`）。資料以外の二次情報のみ → 二次情報のみと明示（Reference：`SUPPORTED`）。どちらも不可 → 未確認（Reference：`UNVERIFIED`） | 一次情報が存在しない場合の扱いを定め、出典の捏造や関連するだけの公式ページの流用を防ぐため。既存の「二次情報しか確認できない場合は明示」と矛盾させないため |
| 循環根拠の禁止 | 二次情報の資料そのものを、その資料の主張の根拠にしない | 本件の中心的な誤り（提示記事を自らのEvidenceとした）を直接禁止するため |
| 矛盾の扱い | 資料と一次情報の矛盾は調査結果として示す | 真偽確認では矛盾の発見自体が成果であるため |
| 出力前確認 | Evidenceと主張の対応、作業メモ・思考過程の混入を確認し、確認の過程・結果は出力しない | 混入対策。ただし効果は実出力で検証する |
| Reference 9章 停止条件 | 「前提が一次情報と矛盾」での停止を、対象・目的の変更判断が必要な場合に限定。矛盾は根拠付きで報告し調査を継続 | 真偽確認の途中で停止する解釈を防ぐため |
| Reference 11章 誤り時の原因 | 原因は確認できた範囲だけを示し、確認できない場合は「未特定」、仮説は `INFERENCE` として分ける | 原因説明の義務化が、本件レポートのような推測の原因説明を生むことを防ぐため |

### 3.3 不採用とした案

- Gemが提案した3か所の【重要】追加（3章・5章・8章）
  - 「URL＋短い質問」に限定した適用条件では、貼り付け文や画像等が対象外になるため。
  - 「必ず一次情報をEvidenceとする」は一次情報が存在しない場合の手順がなく、既存規則と矛盾し、出典捏造を誘発し得るため。
  - 同趣旨の規則を3か所へ分散させるため。
- User提示資料をすべてEvidenceから除外する案（Claude初回修正案）
  - 公式仕様書の提示まで除外し、要約依頼にも外部検索を強制するため（レビュー指摘R1）。
- 出所を問わず二次情報だけでは確認済みにしない案
  - Career Module の企業研究等、二次情報中心の調査まで一律に制限するため。
- 「指示の先頭に『Researcherペルソナで』と書く」運用対策の標準化
  - 根拠が未検証の原因説明に依存するため。再検証テストで効果を確認するまで採用しない。
