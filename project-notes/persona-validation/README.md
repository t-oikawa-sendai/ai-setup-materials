# Persona検証記録

## 検証目的と対象Persona

GitHub上の検証用Personaを、新規チャットでAIが取得するか、未取得のときに未読込と申告するか、Versionが一致するかを記録する。応答の揺らぎを見るため、数日〜数週間の継続検証を前提にする。1回の回答で優劣や順位は決めない。

対象Personaは `personas/reference/IT_GENERAL_ADVISOR_TEST_PERSONA.md` である。

- Persona ID: `IT-GENERAL-ADVISOR-TEST`
- Version: 0.1
- Status: Draft
- Verification Code: `ADVISOR-ALPHA`

このPersonaは中核4種Reference Personaの本文編集元ではない。検証記録の追加によってVersionやStatusは変えない。

2026-10-14の記録は、上の検証用Personaに対するものである。

2026-10-15の記録は別件である。対象は `personas/reference/CHATGPT_PERSONA.md`（Persona ID `M-CG`、Version 1.2（提案）、Status Draft）について、ChatGPT Project、Claude Project、Gemini Gemで実施した D-025 の TC-01〜TC-03、各2回である。この記録の追加は、Version、Status、Approvedを変えない。検証用Personaの記録と混同しない。

正規比較に使うChatGPTの結果は、検証専用Projectの再テスト 4/6 である。先に保存した従来Projectの 6/6 は参考履歴である。Claude 2/6、Gemini 3/6 と合わせた正規比較は 9/18 である。累積原文24件と正規比較対象18件は別である。区別は `SUMMARY.md` と `project-notes/DECISIONS.md` の D-032 に従う。

## 原文・評価・総合集計の分離

| 場所 | 役割 |
|---|---|
| `raw/` | 提出された原文と、その日のマニフェスト。評価文を置かない |
| `assessments/` | 日別の評価。事実、自己申告、未確認、評価者の見解を分ける |
| `SUMMARY.md` | 期間の件数集計。原文を複製しない |

評価基準が後から変わっても、原文へ戻れるようにする。評価結果で原文を置き換えない。

## 原文の改変禁止とチェックサム管理

`raw/` の原文は、改行、空白、文字参照、表記、バックスラッシュを含め、バイト列を変更しない。書式が不自然に見えても修正しない。

各原文のSHA-256を、その日の `raw/` マニフェストに記録する。保存後に `shasum -a 256` で照合する。同名ファイルが既にある場合は上書きせず、内容を照合する。

2026-10-14の照合値は `raw/2026-10-14-manifest.md` に記録されている。2026-10-15の照合値は `raw/2026-10-15-manifest.md` に記録する。2026-10-14のファイルは変更しない。

| `raw/2026-10-14-user-submitted-source.md` | `225a7bb7b6a2bf96f5fc1f5db4eb91ead28ef2278ef1f0277f8cc12bc990b63b` |
| `raw/2026-10-14-gemini.md` | `d5d0086dea2b62f3135a7cda223fc26e6a66516707053c5f287f76f47ef369bd` |

`original-uploads/` は受領時の元データ保存用であり、このRepositoryへ一括では置かない。

## 実行条件の記録方法

日別評価には、確認できた範囲で次を残す。

- 検証日
- 検証質問
- AIサービス
- 原文にある自己申告タグ
- 出典の位置づけ（User提出テキストか、元画面の直接証跡か）

実行時刻、正確なモデル識別子、利用機能、設定差が提出記録から確認できない場合は、未確認のままにする。推測で埋めない。

## VERIFIED / UNVERIFIED の区別

ファイルの存在、バイト数、SHA-256の一致は、照合した作業で確認できたものだけをVERIFIEDとする。

各AIが書いた「GitHub読込済」または「GitHub未読込」は自己申告である。元画面、取得操作、APIログなどの技術的な取得証跡がない場合、実際のGitHubアクセスはUNVERIFIEDとする。自己申告を取得の証明として扱わない。

回答内容の正確性は、原文の保全とは別に評価する。未実施の評価を実施済みと書かない。

## 継続検証時の記録追加方法

1. 新しい原文を `raw/` へ、日付とAIサービスが分かるファイル名で追加する。既存の原文ファイルは変更しない。
2. その日のSHA-256を `raw/` のマニフェストに記録し、保存後に照合する。
3. 日別評価を `assessments/YYYY-MM-DD.md` に追加する。原文の全文は評価ファイルへ複製しない。
4. `SUMMARY.md` は、確認できた検証日と回答件数を、検証の種類ごとに更新する。実施済みの回答内容のPASS/FAILがある日は、その件数をその日の節へ残す。順位は記入しない。未実施の評価を実施済みと書かない。

質問の種類、反復の頻度、同一条件の定義は、Userが決めるまで空欄のままにする。

## 公開情報の安全確認とバックアップ方針

このRepositoryは公開されている。認証情報、秘密情報、個人を特定できる情報、ローカルパスは置かない。原文を追加する前と、pushを検討する前に確認する。

保全はGitHubの履歴と、それとは独立したバックアップを併用する。バックアップ先のパスと方式は未決定である。決まるまで、バックアップ先を推測して記録しない。
