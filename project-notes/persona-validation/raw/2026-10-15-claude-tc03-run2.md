### 結論

殿！ 次に行うのは **commit前の独立レビュー** です。commit／pushの許可はすでにいただいていますが、実行するのは**独立レビューがPASSしてから**です。

| 項目          | 判断                                 | 根拠                                   |
| ----------- | ---------------------------------- | ------------------------------------ |
| 次の作業        | 独立レビュー依頼文を作成し、殿！から独立レビュー担当へ渡していただく | §5、§7                                |
| commit／push | 許可は有効だが、実行は保留する                    | §5「認証・権限の重要変更は例外なくcommit前の独立レビューを必須」 |
| 実装テスト       | 既存のPASS結果をそのまま使い、再テストはしない          | §5「同じ目的の再検証は行わない」                    |
| 独立して進められる作業 | 認証・権限と関係のない作業は続けてよい                | §6                                   |

> **用語の補足**
>
> - **独立レビュー**：設計や実装に関わっていない別の担当者が、変更内容を確認すること。作った本人の見落としを防ぎます。
> - **commit**：変更をGitの履歴に記録すること。**push**：その記録をGitHubなどのリモートへ送ること。

### 手順

| 順  | 作業                                                     | 担当          |
| -- | ------------------------------------------------------ | ----------- |
| 1  | 実装担当が提出したEvidence（差分とテスト結果）が、完了条件を満たしているか確認する          | 設計担当        |
| 2  | 独立レビュー依頼文を作成する（下記参照）                                   | 設計担当        |
| 3  | 依頼文を独立レビュー担当（運用例ではClaude）へ渡す。自動送信はしない                  | 殿！          |
| 4a | **PASSの場合**：いただいている許可にもとづき、commit、続いてpushを行う           | Cursor      |
| 4b | **FAILの場合**：commitせず、指摘された点だけをCursorで修正し、その範囲だけ再レビューする | 設計担当→Cursor |

**ASKME（殿！のご判断が必要な点）**

- 4bで差分が変わった場合、今いただいているcommit許可が修正後の差分にも有効かどうかは、規則からは決められません。その時点で殿！にご確認いただきます。

### 独立レビュー依頼文（そのまま渡せる形）

架空のため、実際の値が分からない項目は「未取得」と記しています。
```
【独立レビュー依頼：認証・権限変更（commit前必須レビュー）】

1. Repository：未取得（owner/name、URL）
2. branch：未取得
3. 対象：未commit差分（commit SHAは未作成）
4. 確定仕様：未取得（承認済み仕様の該当箇所と、承認の経緯）
5. 変更範囲：認証・権限に関する変更（対象ファイル一覧は未取得）
6. 検証Evidence：実装担当の実装テストはPASS（テスト名・実行ログは未取得）
7. 重点確認事項：
   - 認可の抜け（権限チェックをせずに処理へ進める経路がないか）
   - 権限昇格（下位権限で上位操作ができないか）
   - 失敗時の扱い（エラー時にアクセスを拒否する側へ倒れているか）
   - 秘密情報（キー・トークン等）がコードやログに出ていないか
   - 確定仕様にない挙動や、対象外の変更が混ざっていないか
8. 合否条件：
   - PASS：上記で問題がなく、差分が確定仕様と一致している
   - FAIL：問題を1件でも検出した場合（該当箇所と必要な修正内容を添えて報告）
9. 独立性：本変更の設計および実装を担当した者・作業セッションとは別の者が実施すること
```

**補足**：対象RepositoryのAGENTS.mdなどに、これより厳しいレビュー規則がある場合は、そちらに従います。
