# Code Generator 5パターン横断比較（参考資料）

## 1. 目的

同一の「どこつぶ」実装課題を基準に、次の5パターンを横断比較した静的レビュー結果を参考資料として整理する。

1. GPT-5.6 Sol
2. Claude Opus 5 High
3. Gemini 3.5 Flash Lite
4. Gemini 3.1 Pro Personaなし
5. Gemini 3.1 Pro + Code Generator Personaあり

本資料は、モデル一般の性能を示すベンチマークではない。

特にPersonaの効果を確認するときは、同一モデル・同一プロンプトで比較した `Gemini 3.1 Pro Personaなし / Personaあり` のA/B比較を主Evidenceとする。5パターン横断比較にはモデル自体の差も含まれるため、Persona効果だけを示す資料としては扱わない。

## 2. 検証条件

- 対象：Java / Spring Boot / JSP / JDBCによる「どこつぶ」実装出力
- 比較方法：コード、POM、JSP、SQL、構造の静的レビュー
- Maven実ビルド：未実施
- 実行時動作：未確認
- 評価値：今回の出力に対する相対評価

## 4. Code Generator適性の順位

| 順位 | パターン | 主な理由 | 主な注意点 |
|---:|---|---|---|
| **1位** | GPT-5.6 Sol | 明示要件・制約への忠実度が高く、純JDBC・単純なMVC構成で初学者教材として扱いやすい | Stored XSSなどセキュリティ面の弱点がある |
| **2位** | Gemini 3.1 Pro + Code Generator Persona | Personaなしから認可、例外処理、セッション、XSS、DB設計、責務分離が大幅に改善 | `spring-boot-starter-jdbc`、`schema.sql`、指定Lombok、WAR構成などHard Constraint遵守に課題が残る |
| **3位** | Claude Opus 5 High | DB設計、XSS対策、保守性、全体設計品質が高い | 要求外の設計追加が多く、今回のCode Generator責務では介入が強い |
| **4位** | Gemini 3.1 Pro Personaなし | Gemini 3.5 Flash Liteより構造化は進んでいる | コンパイル阻害候補、例外処理、認可、セッション、HTTP設計などに重大な問題が残る |
| **5位** | Gemini 3.5 Flash Lite | MVC / CRUD / PreparedStatementなど基本形は生成できる | JSP、依存関係、DataSource、例外処理などプロジェクト全体の静的整合性が弱い |

## 5. 読み方

この順位は「どのAIが一般に最も優秀か」を示すものではない。

今回の目的は、職業訓練校の初学者向けCode Generatorとして、次を重視した場合の相対評価である。

- Userが明示した要求・制約を守る
- 不要な仕様追加を抑える
- 初学者が構造を追いやすい
- 静的に見て実装全体が成立しやすい
- セキュリティ・例外処理・責務分離に重大な欠陥が少ない

そのため、コード単体の設計品質だけを見る場合はClaudeが上位になり得る。また、Personaの有効性を判断する場合は、5モデル横断順位ではなくGemini 3.1 ProのPersonaあり／なしA/B比較を優先して読む。

## 6. 主要な示唆

- GPT-5.6 Sol：仕様忠実型
- Claude Opus 5 High：自律品質改善型
- Gemini 3.1 Pro + Code Generator Persona：Persona補正型

Gemini 3.1 ProではPersona適用後、認可、例外処理、セッション設計、XSS、HTTP設計、DB設計、責務分離が改善した一方、明示制約遵守には課題が残った。

したがって、今回の検証から言えるのは「Personaがモデルを単純に賢くする」ということではなく、**モデルが持つ能力をどの判断基準・優先順位で使うかに影響する**という点である。
