# AI活用教育における段階的導入方針

- 作成日：2026-08-20
- 対象：職業訓練校の初学者向けAI活用教育
- Status：CONFIRMED

## 背景

生徒は最初からAIをフル活用してアプリやポートフォリオを開発できるとは限らない。
初期段階では、AIの主な用途は学習支援、最新情報の取得、コード理解、エラー解析、練習問題、相談などになる。

そのため、開発運用のためのファイルやルールを最初から一括導入すると、AI活用そのものより運用管理の理解負荷が高くなり、混乱を招く可能性がある。

## 確定方針

AI活用教育は、利用目的と開発複雑度に応じて段階的に導入する。

### 段階1：学習・調査

主な用途：

- 学習内容の解説
- 最新情報の取得
- コードの意味の確認
- エラー原因の整理
- 練習問題の作成
- 就職活動や技術調査の支援

この段階では、`AGENTS.md` や `SKILLS.md` は導入しない。

### 段階2：小規模な制作

主な用途：

- 小規模Webアプリ
- 課題制作
- 小規模なポートフォリオ

この段階では、README、要求・要件、簡単な設計文書などを中心とし、運用ルールを増やしすぎない。

### 段階3：AIを利用した継続開発

複数ファイル、DB、API、Git、テスト、複数AI、複数セッションなど、開発の複雑度が上がった段階で `AGENTS.md` の導入を検討する。

`AGENTS.md` の役割：

> プロジェクト全体でAIが守る恒久的なルール、責務、権限境界、正本、禁止事項などを定義する。

### 段階4：作業手順の再利用・高度なAgent運用

特定作業を繰り返し安定して実施する必要が出た段階で、Skillsを導入する。

概念上の役割分担：

```text
AGENTS.md
= プロジェクト全体でAIが守るルール

SKILLS/
├─ database-review.md
├─ release-check.md
└─ security-check.md
= 特定作業をどう実行するかを再利用可能な手順として分離
```

`SKILLS.md` / `SKILLS/` は、`AGENTS.md` よりも後の段階で導入する。
理由は、Skillは「AIに何を守らせるか」ではなく「特定作業をどのように実行させるか」を部品化する考え方であり、初学者には追加の抽象概念になるため。

### 段階5：高度な継続運用

必要に応じて `CURRENT.md` などを導入し、複数AI・複数セッション・並行開発での現在地点や引き継ぎを管理する。

これは基本的なAI活用と開発運用を理解した後の応用とする。

## 教育上の原則

- AI運用の仕組みは、必要になる前に教えすぎない。
- 「便利だから全部導入する」ではなく、学習段階と実際の困りごとに応じて導入する。
- `AGENTS.md`、Skills、`CURRENT.md` は、それぞれ異なる問題を解決するものであり、一括して初心者へ与えない。
- Education用4Gem（Researcher / Solution Partner / Implementer / Reviewer）は、これらの高度な運用ファイルを理解していなくても利用できる設計とする。

## 再提示ルール

今後、以下に関する話題が出た場合は本方針を再提示・参照する。

- 生徒向けAI教育の段階設計
- `AGENTS.md` をいつ教えるか
- `SKILLS.md` / Skills をいつ導入するか
- 初心者に開発運用ルールをどこまで与えるか
- 4Gemとプロジェクト運用ファイルの関係
- `CURRENT.md` を生徒へ導入する時期
