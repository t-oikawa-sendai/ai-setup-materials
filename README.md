# ai-setup-materials

AIエージェントに与える設定・ペルソナ定義の配布リポジトリです。

仕様駆動開発（SDD）を前提に、AIへ「役割」「禁止事項」「入出力形式」を明文化して渡すための定義書をまとめています。

## 目的

AIに曖昧な依頼をすると、推測による補完、指示外の変更、根拠のない完了報告が発生します。
本リポジトリの定義書は、これらを構造的に防ぐための制約をあらかじめ言語化したものです。

## 構成

```
personas/
├── education/   学習用：Gemini内の4つのGemで開発工程を完結させる構成
└── reference/   参考：複数のAIサービスを役割分担させる実務構成の例
```

### personas/education/

`GEMINI_PERSONA_DEFINITION-4Gem.md`

Geminiの Gem 機能を使い、リサーチ・設計・実装・レビューを4つの独立したGemに分離して運用する定義書です。
各Gemはコンテキストを共有せず、人が確定した仕様のみを手渡します。

含まれる内容：

- 4Gemそれぞれのカスタム指示（そのままGemへ貼り付けて使用）
- 環境情報を登録するパーソナライズ設定テンプレート
- 調査 → 設計 → 実装 → レビューの手動リレー手順
- 検証・完了判定の規約

### personas/reference/

`CLAUDE_PERSONA.md` / `CHATGPT_PERSONA.md` / `CURSOR_PERSONA.md` / `GEMINI_PERSONA.md`

複数のAIサービスに役割を割り当てて運用している実務構成の例です。
学習用とは前提が異なるため、そのまま流用すると動作しません。読み物として参照してください。

## 使い方（学習用）

1. `personas/education/GEMINI_PERSONA_DEFINITION-4Gem.md` を開く
2. 第2章のパーソナライズ設定を、自分の環境（OS・IDE・パス）に合わせて `【 】` 部分を書き換える
3. 書き換えたテキストをGeminiのパーソナライズ設定に登録する
4. 第3章の4つのカスタム指示を、それぞれ別のGemとして登録する
5. 第4章の手順に従い、Gem間を手で渡しながら開発を進める

`【ユーザー名】` などの `【 】` および `<repository-name>` は、各自の環境に置き換えるプレースホルダです。

## 前提と注意

- 定義書は特定のプロジェクトの運用実績をもとにしています。そのまま最適とは限りません
- パスワード、APIキー、接続情報などをAIへの入力・出力・公開物に含めないでください
- AIの「完了しました」という報告は、動作の確認結果ではありません。必ず自分の環境で確認してください
